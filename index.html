一、超休闲游戏定义与核心设计理念

1.1 核心定义

超休闲游戏（Hyper-Casual）本质上是一种精确的商业-体验工程：在极短的开发周期内，用最小交互单元捕获最大规模的泛用户注意力，再通过广告变现（IAA）实现经济闭环。

创新组采用的判定标准（海外移动端 IAA 基准）
CPI < $0.30  |  单局时长 < 3 分钟  |  D1 留存 > 35%  |  原型验证 ≤ 2 周  |  核心交互可一句话说清

1.2 设计四天条

天条释义检验方法
一触即懂无需教程，3 秒理解核心操作随机找 3 人试玩，不说规则，看能否自行开始
一秒上瘾操作后 1 秒内获得清晰反馈关掉声音/特效后是否仍有操作冲动
永远再来一局单局极短 + 失败成本低 + 微进步感知观察试玩者失败后是否自发点重试
广泛共鸣主题不依赖特定文化或年龄层给三个不同年龄/背景的人看截图，能否 2 秒说出在玩什么

1.3 核心循环机制

趋势判断
2024-2026 年行业向混合休闲迁移明显。建议以超休闲为切入标准验证核心循环， 同时在架构上预留 Hybrid 扩展接口（皮肤解锁、轻赛季），以便验证成功后提升 LTV。
创新组启示
  • 第一款产品严格对标超休闲标准（1 个核心机制、2 周原型），降低验证成本。
  • 架构设计时预留 Hybrid 扩展点（皮肤系统、排行榜接口），避免验证成功后推倒重做。
  • 四天条可作为内部创意评审的硬性准入门槛。

原则操作定义

创新组启示

  • CPI 测试应作为最早的外部验证环节，在产品打磨之前完成。
  • 关卡基因模板是后续 AI 生成管线的基础——P2 阶段即应开始定义。

三、指标适用边界：不同市场与品类的指标差异

适用边界说明
前述指标（CPI < $0.30, D1 > 35% 等）主要来自海外移动端 iOS/Android IAA 超休闲的行业基准。 创新组同时关注国内小游戏、Hybrid-casual、Steam 小体量验证等场景，直接套用可能导致误判。 本章明确各场景下指标的适用性和修正方向。

3.2 使用建议

  1. 确定目标场景后，先查本表确认指标基准，避免默认套用海外 IAA 数值。
  2. 指标互相校验：例如国内小游戏 D1 留存偏低是正常现象，但如果分享率也低，则说明产品本身存在问题。
  3. 混合场景下取交集：如果同一产品计划同时上海外移动端和国内小游戏，以更严格的指标为准。
  4. Steam 验证是独立逻辑：不走 CPI/留存体系，走"作品质量 + 社区口碑"逻辑，适合验证有深度但小众的创意。
建议的场景选择
优先选择海外移动端 IAA作为主赛道（指标体系最成熟、验证链路最短）， 同时用微信小游戏做平行低成本验证（无需买量，用分享率快速判断游戏性）。 Steam 验证可留作后续阶段，当 AI 管线成熟后用于验证谜题类创意。
创新组启示
  • 所有评审文档应标注"指标场景"字段（海外IAA / 国内小游戏 / Hybrid / Steam），避免跨场景混用指标。
  • 微信小游戏可作为零成本的"游戏性验证"通道——分享率本身就是对核心循环质量的市场投票。

四、竞品关卡算法四层拆解方法论

关卡设计的核心能力在于能把任何一个竞品的关卡还原为可复现的参数和规则。以下是创新组标准化的四层拆解框架。

拆解流程
拿到任何竞品后，按 Layer 1 → 4 的顺序依次拆解。每层有标准化问题清单。 拆解结果直接填入模板表格，作为后续 AI 生成管线的输入。

Layer 1: 表层拆解 —— 玩家看到什么、做了什么

记录可观测的表面信息，不涉及算法层面的分析。

拆解维度标准化问题记录示例（Going Balls）
目标玩家在这一关要完成什么？胜利条件是什么？控制球到达终点平台
核心操作玩家的输入方式？几种操作？左右滑动（1 种输入）
障碍物类型有几种障碍？静态/动态？致命/减速？旋转平台（动态致命）、缺口（静态致命）、减速带（静态减速）
空间布局2D/3D？线性/分支？视角？3D 线性下坡轨道，第三人称跟随视角
反馈系统成功/失败分别有什么反馈？通过障碍物时金币+粒子特效；失败时碎裂动画+震动
广告触发点在哪些节点弹广告？失败后激励视频复活；每 3 关一次插屏；结算页倍数奖励

Layer 2: 规则拆解 —— 关卡的"问题类型"是什么

将关卡的核心挑战抽象为问题类型。同一个游戏的不同关卡，本质上可能属于不同题型。

问题类型定义典型游戏AI 生成难度
排序问题将元素按规则排列Water Sort、Nut Sort低——规则明确，约束求解即可
路径规划在约束空间中找到通路Draw To Smash、Roller Splat中低——可用图算法生成并保证有解
反应/时机在正确时间点做正确操作Going Balls、Stack Ball中——需调校时间窗口和速度曲线
空间推理在空间中做几何判断Woodoku、Block Puzzle中——需保证有解且解唯一/可控
概率/风险决策在不确定性中做选择Lucky Looter、Mob Control低——概率参数可直接配置
资源管理在有限资源约束下达成目标Candy Crush-like、合成类中高——需确保可达性和难度平衡
拆解产出
为目标竞品的前 50 关标注题型分布（如：30% 反应/时机 + 40% 路径规划 + 30% 混合）， 该分布直接决定 AI 生成管线需要覆盖的算法类型。

Layer 3: 参数拆解 —— 难度的"旋钮"

同一个题型，难度高低由以下可调参数控制。拆解时逐一识别并量化。

参数维度释义量化方法影响方向
对象数量场景中元素/障碍物的总数直接计数数量增加 → 搜索空间增大 → 难度上升
障碍密度单位空间/时间内的障碍物密度障碍数 / 通道长度密度增加 → 反应时间减少 → 难度上升
容错次数允许犯几次错直接读取容错减少 → 压力增大 → 难度上升
空间大小棋盘尺寸、通道宽度格子数 / 像素宽度空间缩小 → 精度要求提高 → 难度上升
隐藏信息量多少信息对玩家不可见隐藏元素数 / 总元素数隐藏增加 → 需要记忆/推理 → 难度上升
时间压力是否有倒计时、速度是否递增时间限制(秒) / 速度乘数压力增加 → 决策质量下降 → 难度上升
新机制引入频率每隔几关引入新障碍或规则新机制间隔关数过密 → 认知负荷上升
参数记录模板
对竞品前 30 关逐关记录参数值，用于生成参数变化曲线。
Level_01: { objects: 5, density: 0.2, lives: 3, grid: 4x4, hidden: 0%, time: none }
Level_15: { objects: 12, density: 0.5, lives: 2, grid: 6x6, hidden: 30%, time: 60s }
Level_30: { objects: 18, density: 0.7, lives: 1, grid: 8x8, hidden: 50%, time: 45s }

Layer 4: 生成逻辑拆解 —— 关卡的"制造方式"

通过对关卡结构规律的分析，推断竞品可能采用的关卡生成方法：

生成方法特征识别适用题型AI 接管可行性
纯手工设计每关差异大、有明显"意图感"叙事性关卡、Boss 关低——需保留人工设计
模板 + 参数化结构相似但参数不同物理避障、Runner 类高——AI 生成的主要方式
规则随机生成每次进入同一关布局不同无尽模式、每日挑战高——规则约束 + 随机种子
解空间约束生成每关保证有解且难度可控排序类、拼图类、数独变体高——天然适合"先生成解再构造题目"
先解后关（Reverse）生成完成态后反向打乱Match-3 棋盘、华容道高——数学上可保证有解
数据驱动调参同一关不同用户参数略有不同所有类型（线上微调）中高——需线上数据回流支撑

4.5 四层拆解总结

Layer 1 表层 Layer 2 规则 Layer 3 参数 Layer 4 生成 看到什么/做什么 ──▶ 什么题型 ──▶ 哪些旋钮控制难度 ──▶ 关卡怎么制造出来 │ ▼ [输出: 关卡基因模板 + 生成策略] [直接作为 AI 管线的输入规格]
创新组启示
  • 每个新品类立项时，应先完成至少 3 款竞品的四层拆解，形成拆解档案。
  • Layer 3 参数记录模板可标准化为团队统一的 JSON Schema，直接对接生成管线。
  • Layer 4 的生成方法判断直接决定 AI 管线的技术选型——优先选择"模板+参数化"和"先解后关"类品类。
  • 对于二合类（当前任务）：本章的四层拆解方法完全适用，但"生成目标"不是关卡池，而是物品链 Schema、订单配置和生成器参数表。Layer 4 对应的核心资产是 item_chain_schema.json 和 generator_config.json。

五、从人工拆解到 AI 管线：映射与转化

传统团队依赖人工完成关卡质量保障的全流程。以下将每个人工环节映射到创新组 AI 管线的对应能力。

5.1 映射总表

传统人工做法 具体内容 AI 管线替代 实现方式
人工体验记录 设计师试玩竞品，手动记录每关体验感受与卡点 → 自动事件采集 埋点 SDK 采集全流程事件；AI 生成结构化体验报告
压力曲线手绘 设计师凭经验画出难度曲线，人工排关 → 关卡难度自动评分 基于 Layer 3 参数加权计算 difficulty_score；自动排序符合锯齿波模型
多人跑测 3-10 人不同水平的测试者试玩并记录数据 → 多 Agent 仿真 三档 Agent 跑测每关；输出预估完成率、失败热力图、时长分布
人工复刻竞品 参考竞品在引擎中手动搭建类似关卡 → 参数化批量生成 竞品拆解为参数模板 → AI 在参数空间内批量采样生成候选关卡
人工复盘调参 周会复盘数据，凭经验微调 → AI 自动诊断报告 每日生成关卡健康度报告：标红超出健康区间的关卡，附调参建议
人工排关 设计师手动排列关卡顺序 → 自动关卡排序 基于 difficulty_score 和 novelty_score 自动编排关卡序列
直觉判断质量 资深设计师试玩后主观评价 → 多维评分卡 五维打分 → 加权总分 → 自动淘汰低分关卡

5.2 分工原则

AI 与人工的边界
AI 管线替代的是重复性劳动和规模化生产环节，保留创意判断和手感调校由人工完成。

AI 负责：批量生成 → 自动跑测 → 指标评分 → 筛选排序 → 异常诊断
人工负责：关卡基因模板设计、新机制创意、手感/juice 调校、最终质量审核、广告节点策略

5.3 数据闭环

[关卡上线] ──▶ [真实玩家数据回流] ──▶ [AI 自动诊断] ──▶ [更新难度评分模型] │ │ │ 持续闭环 │ └─────────── [生成新候选关卡] ◄── [修正仿真 Agent 参数] ◄──────┘ 核心价值：每上线一批关卡，AI 的预测准确度都在提高
创新组启示
  • 映射表可直接作为 AI 管线各模块的需求文档，按左列→右列逐一开发。
  • 初期应优先实现"参数化批量生成"和"多 Agent 仿真"两个核心环节，其余可后续补齐。
  • 数据闭环是长期竞争力所在——越早接入真实数据，仿真准确度提升越快。

六、AI 落地分阶段路线

推进原则
按"投入产出比最高、风险最低"的顺序逐阶段推进。 每个阶段设定明确验收标准，达标后进入下一阶段。避免在早期阶段引入过高的技术复杂度。

阶段一 规则 + 参数化生成（第 1-4 周）

项目内容
目标基于 Layer 3/4 的拆解结果，用 Python 脚本实现关卡参数化生成器。在参数空间内均匀采样并做约束过滤。
技术栈Python 脚本（约束随机 / 先解后关） + JSON 关卡描述 + Unity 关卡加载器
边界本阶段不涉及 ML 模型训练、RL Agent、GAN/VAE。
验收标准输入难度目标 (1-10)，批量生成 100 关，人工试玩抽样审核通过率 > 15%
投入1 人 × 2-3 周

阶段二 启发式 Agent 跑测（第 3-6 周）

项目内容
目标用基于规则的启发式 Agent逐关跑测。设三档 Agent（新手/普通/高手，对应犯错概率 40%/15%/3%）。
技术栈Python / Unity C# 脚本，状态机 + 概率决策树，无需 ML 框架
边界本阶段不训练 RL——启发式足以满足早期需求，无需引入训练环节的复杂度。
验收标准Agent 预估完成率 vs 真实玩家完成率，误差 < 20 百分点
投入1 人 × 2-3 周（可与阶段一后段并行）

阶段三 自动评分与可视化看板（第 5-8 周）

项目内容
目标搭建自动评分管线 + 关卡健康度看板：Agent 跑测数据 → 五维评分 → 自动排序 → 自动淘汰 → 可视化。
技术栈Python 评分脚本 + Streamlit / Grafana 看板 + 关卡池管理 JSON/SQLite
五维评分 可玩性 (25%): 仿真完成率 50-85%
节奏感 (15%): 平均时长 30-120s
挑战感 (15%): 首次失败率 15-45%
新颖度 (20%): 与已有关卡差异度 > 0.15
广告友好 (25%): 60%+ 进度失败占比 > 30%
验收标准端到端流程：输入难度目标 → 生成 100 关 → 自动筛选 Top 20 → 人工审核确认 > 70% 可用

阶段四 真实玩家数据回流（第 8-12 周）

项目内容
目标产品上线后，真实玩家数据回流 → 校正 Agent 犯错概率 → 校正评分权重 → 更新生成参数分布。
技术栈GameAnalytics/Firebase → BigQuery/本地 ETL → Python 分析脚本 → 模型参数更新
关键动作 比对 Agent 预测 vs 真实数据，定位系统性偏差
自动生成每日关卡健康度报告
通过 Remote Config 灰度发布新关卡
验收标准Agent 预估 vs 真实完成率误差 < 10 百分点；关卡上线到数据反馈 < 24 小时

阶段五 高级技术选项（第 12 周+）

项目内容
前置条件阶段 1-4 全部达标，且有 > 10,000 条真实玩家行为数据积累
可选方向 ARL Agent 替代启发式：用 PPO/SAC 训练更精确的仿真 Agent，将预测误差降至 < 5pp
可选方向 B进化算法优化：用 EA 在高维参数空间搜索帕累托最优关卡集
可选方向 C个性化难度调整（DDA）：根据玩家历史表现实时调整关卡参数
当前阶段暂不建议GAN/VAE 生成关卡布局——数据需求量大（>10K 标注关卡），生成结果可控性低，在超休闲场景下投入产出比不理想

6.6 阶段推进总览

P1 规则+参数化 ─┐ │ 可并行 P2 启发式Agent ─┘── P3 评分+看板 ── P4 数据闭环 ── P5 RL/EA/DDA │ │ 产品同步上线 需有真实数据积累 P1-P2 可并行推进，P3 依赖 P1+P2 产出，P4 依赖产品上线，P5 依赖 P4 数据积累
创新组启示
  • 阶段一和阶段二可由同一位开发者在 4-6 周内完成——这是最小化启动成本的关键路径。
  • 阶段五的触发条件是"数据积累量"，不宜按日历推进；数据不足时强行引入 RL 只会增加调试成本。
  • 每个阶段的验收标准应写入团队 OKR，作为季度考核依据。

7.3 多项目并行与横向对比逻辑

多位同学独立完成二合类项目，最终的价值不只是看"谁的产品更好"，更重要的是形成可对比、可学习、可复用的组织知识。

横向对比维度
  • AI 编排效率：同一功能，谁用更少 Prompt 完成？
  • 产品闭环完整度：从启动到广告点有多少路径断点？
  • 配置 Schema 质量：物品链有解率、订单节奏合理性
  • 范围控制能力：谁能在两周内合理收口而不失控？
  • Prompt 可复用性：Prompt 是否足够通用，能给其他人直接用？
对比价值来源
  • 哪些失败原因是共性的？（意味着方法论需要升级）
  • 哪些成功路径可以直接复制？（意味着 SOP 可以沉淀）
  • 哪个 Schema / 配置模板质量最高？（直接成为团队标准）
  • 哪种 AI 工具组合效率最高？（直接更新工具栈推荐）

8.2 推荐方向：二合类 IAA

当前任务推荐：二合类 IAA（Merge 类）
核心理由：
• 完整产品模块覆盖：合成玩法天然包含玩法逻辑、配置表、订单、生成器、广告点、埋点，是单人用 AI 完成完整产品闭环最合适的场景之一
• AI 全栈能力验证最充分：代码、配置、美术、埋点、测试、复盘每个环节都有 AI 的真实介入空间
• 广告点天然成立：空间快满、物品缺口、生成器冷却等核心张力直接对应激励广告场景，不需要强行设计
• AI 美术场景真实：30-60 个主题图标的批量生成需求，能真正验证 AI 美术工作流的价值
• 横向对比价值高：多位同学独立做同品类，可在配置 Schema、Prompt 质量、开发效率上形成有意义的横向对比

主要风险：系统复杂度高于排序类（6+ 相互依赖系统），单人联调难度显著更高——需要明确收口意识，不能等做"完整"再收。

8.3 排序类 / Water Sort 的定位

排序类：关卡生成算法验证方向 / 备选方向
排序类并非不好，而是当前阶段目标不同：

• 更适合验证 AI 关卡生成算法（先解后关、参数化、Agent 自动跑测）
• 更适合"算法管线"而非"完整产品闭环"的验证
• 更适合验证低复杂度场景下 AI 效率的上限
• 可作为二合类核心闭环无法跑通时的备选方向
• 可作为后续独立项目，专门验证"关卡生成 + Agent 测试"能力

不应因为排序类"容易"就推荐给当前任务——容易不等于更有价值，当前任务需要暴露真实问题，而不是绕开复杂度。

8.5 不应误读的判断

不应误读的六点
  1. 不是因为排序类不好，而是当前任务目标更偏完整产品闭环。二者各有适用场景，不是非此即彼的竞争关系。
  2. 二合类不是最轻量方向，但更能暴露单人 AI 全栈开发的真实问题。系统复杂度本身就是验证的一部分。
  3. MVP 边界不是提前锁死，而是在开发中探索、验证和阶段性收口。不能等做"完整"再收口。
  4. AI 不是替代产品判断，而是承担生成、测试、记录和分析。体验判断、手感调校仍是人工工作。
  5. 项目失败也必须沉淀资产，否则才是真正失败。没有资产产出的项目，才是对组织资源的浪费。
  6. 多个同学独立项目的横向对比，比单个项目结果更有组织价值。不要只盯着自己的产品成败，要关注整个组的经验是否在积累。
创新组启示
  • 当前阶段不用再纠结"该做哪个品类"——方向已经明确为二合类 IAA，精力应聚焦在范围收口和资产质量。
  • 排序类评分矩阵保留价值：后续如需验证关卡生成算法，或当前方向调整时，直接参考此表重新评估。
  • 二合类完整闭环，即使质量一般，也是有价值的组织经验；但没有产出资产的二合类项目，则是资源浪费。

为什么是二合类 IAA

  • 能覆盖玩法、配置、美术、订单、广告点、埋点、测试完整产品模块。
  • 广告点天然成立：空间满、物品缺口、生成器冷却直接对应激励广告场景。
  • 是单人策划用 AI 工具链验证完整 IAA 产品闭环的最合适场景之一。

每位同学做什么

  • 独立完成一个二合类 IAA 产品原型（W0 确认主题，W1 核心合成闭环，W2 可玩包）。
  • 没有程序和美术配置，单人策划 + AI 工具链完成全部环节。
  • 重点不是产品成败，而是走通闭环 + 沉淀可复用资产。

两周内验证什么

  1. W1：核心合成循环可演示；物品链有解、不卡死。
  2. W2：从启动到第一个广告点的路径完整可走通。
  3. W2+：完成资产沉淀清单，参与横向对比。

继续 / 调整 / 终止标准

继续推进核心合成闭环跑通，广告点可触发，埋点事件可查
调整范围系统过多导致频繁卡住——收窄至核心合成 + 1 个广告点
考虑切排序类二合类闭环两周仍无法跑通，考虑切换为验证关卡生成算法的排序类方向

即使产品终止，仍应沉淀以下资产

  • item_chain_schema.json——物品链设计参考，下一个同类项目直接对比复用。
  • art_prompt_template.md——AI 图标批量生成 Prompt 模板，整个团队共享。
  • 工程骨架（Unity 项目模板）——下一个项目直接复用，不用重搭初始工程。
  • 埋点配置模板——7 个核心事件定义，下一个 IAA 项目开箱即用。
  • Prompt 记录与复盘——高效路径 + 失败避坑，是团队最具传播价值的软资产。
以 AI 为引擎、以数据为燃料、以体验为目标、以资产沉淀为壁垒
每个人走完一个完整闭环，整个组就积累了一套可复制的方法论。
即使产品没跑通，Prompt、Schema、配置和复盘都是净收益。
